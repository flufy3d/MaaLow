# 燕云十六声（WhereWindsMeet）工作区

游戏包名 `com.netease.yysls`，截图 1080×720。MaaLow 本身的用法见仓库根目录的 README.md，这里只写这个游戏自己的东西。

## 里面有什么

| | 内容 |
|---|---|
| 流水线 `pipeline/` | 启动登录 `LaunchAndLogin`、每日签到 `DailySignIn`、各种弹窗（商城、奖励、物品提示、空闲幻灯片）、自动拾取 `AutoPickup`、找怪开打 `SeekAndFight`、据点 `Cixin`（一键）/ `CixinTeleport` / `CixinRoute`、`Foye`（一键）/ `FoyeTeleport` / `FoyeRoute`、`Jiurou`（一键）/ `JiurouTeleport` / `JiurouRoute`、`StrongholdFight` |

## 据点：慈心山院

**一键：`Cixin`**（2026-10-01 跑通）。从大世界、菜单、江湖行、据点挑战页、开着的大地图都能开始：关弹窗 → `CixinTeleport` 传送到石碑 → `CixinRoute` 走完路线：进大门，销毁 4 朵毒花，打精英怪，路上遇到的绣金卫边走边打，最后开据点宝箱。

* **刷新**：据点被攻占后约 20 小时刷新。卡片上写着「势力重新占据时间」（`Teleport_NotRefreshed`，OCR 认，剩余时间记进 memory 的 `stronghold_wait`）时，传送照样走完，`Cixin` 停在石碑报错，不跑路线。单独跑 `CixinTeleport` 不受影响，跑分和调试照常
* **离开据点会重置进度**：传送走后再回来，没做完的毒花和绣金卫都会刷回来。所以调试时只要最后一项不做完，就能一直重来（路线参数 `skip: [14]` 留下第四朵花）；正式跑必须一口气做完
* **传送**：卡片打开的大地图以据点为中心，但缩放沿用上次留下的值。先点一下 (434,476) 收起说明面板（放到最大时这一下就点中了石碑），再找离据点图标最近的石碑图标（放到最大时总在 155 px 外；人站在石碑上、箭头盖住它时也能认出，约 0.78）。认不出据点图标说明地图是缩小的，就以据点为中心双指放大 4 次；石碑图标是过一会儿才出现的，没认出就等 1 秒再看。最多 3 轮，不行就报错，不盲点。开着别处的大地图（左下「标点筛选」）就先退出来
* **路点坐标**：大地图放到最大时，相对据点图标的像素，x 向东、y 向南，用的是灰色（已攻占）图标的坐标系。录点用 `stronghold.js` 的 `where()`：点小地图打开大地图，人物箭头固定在 (537,362)，认出据点图标就能算出位置。红色活图标模板的中心比灰图标偏 (−1,−2)，`where()` 会自动换算；第 0–14 点是据点活着时记的，2026-10-01 统一减了 (1,2)。人站在图标旁边时箭头会把它挡住，这时改认图标左上方的名字标签「慈心山院」，它离图标总是 (53, −50.5)。画面上找不到小地图扇形（菜单、读条）就不开地图，返回 null
* **路线怎么走（连续定位）**：节点参数 `locate: ["locate/cixin_mosaic", "locate/cixin_bigmap"]`。每一帧先按镜头朝向、摇杆方向和当前速度推算位置，再用 `locate()` 在推算位置附近找小地图；拼图认不出就换大地图参考图，可信（分数 ≥ 0.4、比第二峰高 ≥ 0.1）就用它校正。全程不开大地图，只在有动作的点和终点停下
  * 途经点：走到 2.5 px 内，或者越过了这个点（到了它所在的横线上，侧偏不超过 6 px）才转向下一个点。以前 6 px 内就转弯，会切角撞上「石像旁」的石像
  * 终点：2 px 内算到；走过头时只要定位在 3 px 内也算。只认停稳后的真实定位，推算说到了不算（爬台阶时人跑得比推算慢，打完仗定位会断断续续）。认不出就扩大搜索范围，3 秒还认不出算跟丢
  * 离终点 12 px 时松开疾跑，剩下的普通跑，免得冲过头
  * 2 秒没靠近目标算卡住，依次试：跳、左绕、右绕、后退绕大圈；越跑越远 15 px 算跑偏
  * 跑偏、卡住、跟丢：在整张参考图里重新定位（两眼一致才算），从这一段剩下的点里最近的那个接着走，最多重来 2 次
  * 遇敌：右上角图标消失，并且 30 大地图像素内有红点（按当前小地图缩放换算，院外约 13 小地图像素，院内约 26；墙后的敌人不算）。停下交给 `combat`，打完原地拾取，读一次任务栏，再全图重定位，从最近的点接着走
  * 跑路时顺手拾取：右侧出现拾取列表就点它上方空处，不点交互行（销毁、据点宝箱这些不会被打开）
* **路点上的动作**
  * `flower`：转到录点时的镜头朝向，等右侧出现「销毁」就点。没出现就看画面：人物周围大小合理的紫色块（HSV H 118–160）就是花，朝它走一小步，最多 3 步；别的紫色东西不追（追错一次会走进殿里）。点了以后看任务栏毒花计数涨了才算销毁（读条一开始那行字就变白，模板认不出，不能用来判断）；最后一朵是整行消失，要连读两次
  * `fight`（精英怪）：已经开打就直接交给 `combat`；没开打就追最近的红点，一开打就停下交给 `combat`，不再追着跳
  * `chest`：点「据点宝箱」。没出现就看小地图上的宝箱图标（`minimap_chest.png`），朝它走到交互出现。点「确认领取」前用 OCR 读面板，有「领取三份」才确认（扫荡次数取面板默认，等于剩下的避战符，最多 9，老师同意），不是就开着面板停下；然后点完「继续」结算页
* **到宝箱点没有宝箱**（最多 2 轮）：读任务栏。按路线里的毒花点清单，没销毁的（`skip` 掉的不算）沿路线走回去补；任务栏计数比记录的少，说明有一朵误判了，就全部回查一遍；绣金卫那行还在就跑 `StrongholdFight`（只追橙色区域里的红点）清场。然后沿路线回宝箱
* **补的中间点**：「绕开第二个毒花旁的石像」(6,−28.5)。从第二朵花直线去精英怪会撞上花旁的石像，照解困后走的路补的

**调试**：`uv run python workspaces/WhereWindsMeet/tools/route_seg.py FROM TO [x y] [key=json …] out=…json` 用 CixinRoute 的参数只跑一段（比如 `1 6` 石碑到第一朵花，`'skip=[14]'` 留下第四朵），返回带完整日志；goto 的轨迹每 250 ms 一条，带帧号 `seq`，配合 `scripts/grab_frames.py` 抓的帧能对上画面；`tools/plot_seg.py RUN.json OUT.png`（要 `--extra cv`）把轨迹画到大地图上（底图是 `data/wwm/bigmap/composite.png`）。

## 据点：佛爷寨

**一键：`Foye`**，照慈心山院做的：关弹窗 → `FoyeTeleport` → `FoyeRoute`。任务是剿灭 7 个破戒头陀（任务栏按 `tracker` 读「破戒头陀」），没有毒花和固定精英怪；最后开据点宝箱，面板和慈心山院一样（默认领取三份）。2026-10-02 夜里据点已攻占时空跑：传送 + 路线连跑 3 趟都到了宝箱点，路线 56–66 秒、全程不开地图，终点 `where()` 核对 1 px；据点活着时（有橙色区域、有敌人、要打）还没跑过

* **传送**：`FoyeTeleport` 用 `Foye_` 开头的菜单 → 江湖行 → 挑战 → 卡片几步（它们的 next 指向佛爷寨卡片 `stronghold_card_foye.png`，第二张卡），后面说明面板、石碑、传送、落地和慈心山院共用。石碑叫「佛爷寨」，在据点图标西边约 147 px。落地点是 (−154.5, 18.5)，在石碑旁的石头上，往东直走会撞木栅栏，路线第 1 点先往东北下到土路
* **路点**：老师 2026-10-02 用 `where()` 记的 14 个点，加两个补的：「下石碑上土路」和「往南绕过两块立石」（第 7 点直线去篝火会卡在两块立石中间）。宝箱点人站在图标旁边，箭头挡住图标，`where()` 改认名字标签 `map_label_foye.png`（离图标 (−21.5, −110)；同一个标签每次开图分数在 0.68–1.0 之间跳，门槛 0.6，别的地名 ≤ 0.35）
* **小地图缩放和慈心山院不一样的地方**：比例一样（院外 1 小地图像素 = 2.29 大地图像素，进大门后 1.17，按据点图标在小地图上的距离对 33 个锚点拟合，残差 < 1 px），但**关掉大地图后不会先缩小**，从关图后第一帧起就是当前位置该有的缩放，只看在不在大门里面（x ≈ −49 切换）。所以 `track` 要加 `--gate -49`，按锚点位置定缩放；用默认的 `track`（靠大地图参考图逐帧判缩放）会把院内的帧判成院外，拼出来东边那条路是歪的
* **参考图**：`locate/foye_mosaic`（主力）和 `locate/foye_bigmap`（兜底；这一带大地图几乎是空白，单用它离线只有约 1/4 的帧能可信定位）。拼图数据在 `data/wwm_foye`：survey2 是整条路线一趟（开图走、记锚点，47 个锚点），survey4 是东边那条路一趟（`route {dwell: 3500}`：每个锚点站 3.5 秒，攒下位置和缩放都确定的静止帧）。离线测：老师记点时的 12 张截图（据点活着、有橙色）误差都在 1.2 px 内，check 跑的 10 个点和另一趟采集的 13 个锚点都在 1.7 px 内
* **没刷新就停**：说明面板写「势力重新占据时间」时 `Teleport_NotRefreshed` 认出来，`Foye` 在石碑报错停下（2026-10-02 验证）。这个节点原来写的是 `custom_recognition: "stronghold.waiting"`，App 每个技能只注册一个自定义识别 `<技能>.recognize`，所以它从来没认出过（慈心山院的一键入口也一样）；现在是 `stronghold.recognize` 加参数 `{waiting: true}`

## 据点：酒肉山林

**一键：`Jiurou`**：关弹窗 → `JiurouTeleport` → `JiurouRoute`。第一个用 `tools/rec_route.py` 从录像全自动做出来的据点：老师 2026-10-02 录了一趟 20261002-025629（3:18，菜单 → 卡片 → 传送 → 打 → 开箱，没标路点）。任务是剿灭 7 个破戒头陀（`tracker` 读「破戒头陀」），分布在第一个院子、东南的篝火空地、据点图标西边的小院；宝箱在第一个院子里

* **路线**：照老师录像里的顺序走（老师 2026-10-02：「路线别自作主张，我怎么跑都是有考虑的」）：石碑落地 (104, −35.5) → 往西沿土路 → 院门 → 第一个院子（头陀 2、3 倒下的地方）→ 东南篝火空地（头陀 5）→ 西边小院（头陀 6）→ 回第一个院子开宝箱 (27, −23)，31 个点。篝火空地和西边小院都是去了原路折回，和录像一样。头陀 1 在院门外那场打里就死了（任务栏要进了据点范围才出来，第一次读到的 1/7 不算途经点：它落在院门的缩放切换处，第一趟照它跑就在那里停不稳）。路上的头陀交给 follow 模式打，到宝箱点还没清完跑 `StrongholdFight`。第一版是石碑直奔宝箱（只认了宝箱一个目标），老师指出后改了
* **空跑（据点已攻占）**：2026-10-02。直奔宝箱那版两趟都到了（57–68 秒）；第一趟发现拼图坐标统一偏约 2 px，用那趟的 6 次 `where()` 读数修正（`device_anchors.json`）。照老师顺序这版先卡在院子去篝火空地的路上（只有攻占前、带橙色的拼图，没橙色的画面配到没走过的地方，错 5.8 px 却有 0.59 分），于是补采：开大地图短步走过第 10–31 点（`survey2`–`survey4`，约 3600 帧、40 个锚点），并进「攻占后」那层（31 → 153 帧）。之后整条 31 个点一趟走通：`where()` 核对 0.1–2.6 px（大多 ≤ 1.5），没有一次跟丢重定位，362 秒（其中 31 次开图约 280 秒），定位 2250 次丢 32 次，最长连丢 31 帧在院门缩放切换处。一键入口没刷新时在石碑停下（「势力重新占据时间」），约 2026-10-02 23:00 刷新，**据点活着时（有橙色、有头陀、开箱）的整趟还没跑**

## 小地图的几个坑（2026-09-30 采集时发现）

* 小地图上北下南，扇形就是镜头朝向（`lib/minimap.js` 的 `cameraHeading`）
* **院子里会放大一倍左右**：院外 1 小地图像素 ≈ 2.3 大地图像素，院内 ≈ 1.15。关掉大地图后会先缩回去 1–2 秒，所以参考图做成两档（`out` / `in`），每次都试
* **圆盘是半透明的**：背后的天空、树枝、黄叶会透出来。用带通滤波（两次模糊相减，`dog` 1/4）只留下墙线和建筑块
* **据点的橙色区也是半透明的**：底下的建筑还看得见，所以不能整块丢掉。橙色区内外分开滤波（`regions.mode: flat`），去掉色差，只丢掉边线那一圈。橙色本身 H 10–24、S 25–85、V 100–235；地图本身的 S 大约只有 5
* 疾跑约 8 大地图像素/秒，松手后还会冲约 3 px（院外最多约 7）；普通跑约 4.6 px/秒
* 右上角图标逆光时认不出来；大地图打开后，图标大约 2.5 秒才显示出来

* **全程第 1–15 点，每点停下用 where() 核对，3 轮 + 重构后 1 轮**

  * 石碑到宝箱约 100 秒跑动，不开地图

## 从一段录像做据点路线（`tools/rec_route.py`）

新据点优先用这个：老师只录一段录像，不用标路点，工具生成传送节点、小地图参考图、路线节点和一键入口。它不复刻轨迹：录像里人走到过的地方（打架被推开的也算）都是能走的，在这张可走区域图上给相邻目标规划路线。命令都在仓库根目录跑，先 `uv sync --extra cv`

### 1. 录像（老师）

据点活着时录，从大世界开始，一气呵成（中间别传送去别处）：

1. 菜单 → 江湖行 → 挑战 → 点这个据点的卡片 → 卡片地图上点石碑 → 传送
2. **落地后点小地图开一次大地图，停 2–3 秒再关**。这是录像里唯一的绝对位置（大地图要是放到最大的，平时停在最大就行）
3. 跑过去，打怪、做任务（销毁毒花之类），最后开据点宝箱、领奖、点完结算页
4. 录像名改成卡片上的据点名字（如「酒肉山林」），工具用它在据点挑战页上找卡片

### 2. 生成（电脑）

```sh
uv run maalow rec pull <录像>
uv run --extra cv python workspaces/WhereWindsMeet/tools/rec_route.py all data/wwm_<名字> --rec <录像> --name <名字>
```

约 15 分钟（OCR 最慢），数据都在 `data/wwm_<名字>/`（不入库）。`all` 依次跑：拆帧 → 每帧判画面 → OCR 任务栏和交互列表 → 小地图上的据点图标 → 大地图帧（锚点）→ 帧间配准 → 定位 → 离线评测 → 拼图（写进 `templates/locate/<名字>_mosaic*`）→ 规划 → 给老师看的图。每一步也能单独跑（`rec_route.py <步骤> data/wwm_<名字>`，步骤名见文件开头）

### 3. 看结果能不能用

| 看哪里 | 正常 | 不对时 |
|---|---|---|
| `all` 输出的 `k`、`locate.json` 的 `stone_k` | 小地图上同时看到石碑和据点图标的帧 ≥ 10，`mad` < 0.5 px，`bearing_diff` < 2° | 没有 `stone_k`（石碑离据点太远，小地图上没同时出现）就用了默认 2.29，空跑后一定要用设备读数修正；也可以 `--k-out` 指定 |
| `locate.json` 的 `c`、`zone_after` | `c` 各项几 px 以内，`live_out` 和 `live_in` 差 ≤ 2 px；`zone_after` ≤ 3 px | 院内整段放错了地方：看 `plan_view.png` 上院门那里是不是断开、错位 |
| `eval` 的几行 | 院外、院内攻占后可信 ≥ 95%、中位 ≤ 1.5 px；院内攻占前（有橙色）≥ 70% | 「trusted but > 4 px」多而且分散：拼图有问题；连成一段的多半是那段真值漂了（留出块里没有图标） |
| `targets.json` | `stops` 里有宝箱（毒花等），`tasks` 的任务名、总数对 | 交互列表没读到：看 `text.json` 那几帧的 OCR |
| `plan.png`、`plan_view.png` | 路线（绿）在青线圈出的走过区域里面，顺序和老师录像里一样，经过每个红叉（录像里任务计数涨的位置） | 橙色段是不确定（缩放切换那一秒没有位置）或离边缘近（< 1.3 px），点名录像帧给老师看 |

### 4. 写节点、推送

```sh
uv run --extra cv python workspaces/WhereWindsMeet/tools/rec_route.py emit data/wwm_<名字> --name <名字> --rec <录像>
uv run maalow sync WhereWindsMeet --push --exclude 'recordings/**'
```

`emit` 往 `pipeline/stronghold.json` 写（同名的替换）：`<名字>` 一键入口、`<名字>Route`、`<名字>Teleport` 和 `<名字>_` 开头的菜单 → 卡片几步（照佛爷寨的），并裁卡片标题模板 `stronghold_card_<名字>.png`；卡片名默认是录像名，`--title` 可改。推送时排除 `recordings/`，免得把设备上删掉的录像 meta 又推回去

### 5. 设备上空跑、补采、修正（据点攻占后、刷新前）

录像是据点活着时录的，拼图大半带橙色区域；攻占后空跑，小地图上没有橙色，只有老师打完后走过的地方才有「攻占后」那层拼图，别处可能配不准（酒肉山林在院子去篝火空地的路上就卡住了，量过：配到没走过的地方，错 5.8 px 却有 0.59 分）。哪里会配不准事先算不出来（按拼图的覆盖面积、每处用了多少帧都试过，都和实际对不上），所以靠空跑实测：哪段走不通，就在那段补采，自己拼一张没有橙色的，再空跑，直到整条都过。老师照常打一遍就行，不用多录

先在网页上 `maalow do say` 说清楚要跑什么（会频繁开大地图），然后：

```sh
uv run maalow do run <名字>Teleport
uv run --extra cv python workspaces/WhereWindsMeet/tools/rec_route.py dryrun data/wwm_<名字> --name <名字>
```

`dryrun` 用 check 模式从第 1 点跑到终点，每到一个点停下用 `where()` 读位置，报告走通到第几点（`reached`）、哪些点 `where()` 离路点超过 3 px（`missed`），整个结果存成 `dryrun<N>.json`。

* **哪段走不通**（`reached` 没到终点，或者有 `missed`）：从最后走通的点补采到终点

  ```sh
  uv run --extra cv python workspaces/WhereWindsMeet/tools/rec_route.py survey data/wwm_<名字> --name <名字> --points <reached>-<终点>
  uv run --extra cv python workspaces/WhereWindsMeet/tools/rec_route.py mosaic data/wwm_<名字> --name <名字>
  # 然后 plan → view → emit → sync --push，传送回石碑再 dryrun
  ```

  `survey` 用老办法走这几个点（开大地图读位置 → 朝下一个点跑一小段 → 再开图，不靠参考图；每个点 3 px 内算到），全程抓帧（约 8 帧/秒），每次开图都是一个锚点（`teaching/survey/<名字>_<N>/` 存开图前的截图）。路点上的动作不做（只走路）。走完离线定位这些帧：锚点、小地图上的灰色据点图标、帧间配准，k 和起始缩放档用录像量出来的；写进 `survey<N>/track.json`，`mosaic` 把它们并进「攻占后」那层。开图走只在补采时用：它按直线朝下一个点跑，所以只能沿规划好的路点走（都在老师走过的地方），不能拿它当正式跑法
* **一条命令全自动**：`rec_route.py auto data/wwm_<名字> --name <名字>`（最多 `--rounds` 轮）：传送 → dryrun → 从走不通的地方补采到终点 → mosaic、plan、view、emit、推送 → 再来，直到整条通过；老师按停止就停
* **都走通了但 `off` 普遍 > 1 px、朝同一个方向**（拼图坐标整体偏了）：把这趟的 `where()` 读数加进去重做：

  ```sh
  uv run --extra cv python workspaces/WhereWindsMeet/tools/rec_route.py anchors data/wwm_<名字> --run data/wwm_<名字>/dryrun<N>.json
  # 然后 locate → mosaic --name <名字> → plan → view → emit → sync --push，再 dryrun
  ```

  只能加用**当前**参考图跑出来的空跑（读数是那张图的坐标），修正之后，旧的那几趟就不能再加了

卡住的地方先看日志里的 `stuck`（解困动作有没有管用），补采也过不去就把那段画出来给老师看。据点没刷新时跑一键入口 `<名字>`，应该传送到石碑后报「not refreshed yet」停下；刷新后再跑整趟（打怪、开箱）

### 原理

* **定位怎么来的**：每一段同缩放的帧做一次稀疏最小二乘：帧间位移（间隔 7、10、30 帧）、小地图据点图标（位置 = c − k·图标偏移，c 是图标在小地图和大地图上中心的差，每种图标每档缩放一个，两档绑在 2 px 内）、开大地图时的锚点（不剔除）、拼图定位（三轮：拼 → 定位 → 再解），中间加一个很弱的随机游走把打架时什么都没有的帧连起来
* **目标**：交互列表出现「据点宝箱」「销毁」的那段帧就是动作点（位置取中位数，镜头朝向一并取）；任务栏计数变化记下当时位置（图上的红叉）；任务名取计数行去掉前缀的最后 4 个字，OCR 错字按「同类同总数」归到一组取最多的写法
* **可走区域和规划**：相邻帧位置连线、加宽 1.5 px（缩放切换那一秒多的空缺按直线补上，标为不确定），距离变换得到离边缘多远；A* 代价是步长 ×（1 + 2/(离边缘 + 0.5)）；再用 Douglas–Peucker 简化（偏离 ≤ 1.5 px，且每段每一处离边缘 ≥ 1 px，不满足就在最远点再切）
* **佛爷寨检验**（`check`，用 survey2、survey4 的轨迹）：0→2 去掉「下石碑上土路」，规划自己先往东北到 (−148, 12.2) 再上土路，没冲木栅栏；7→9 去掉「往南绕过两块立石」，规划先往南到 (−21, 6.7)，和老师的点差 1.9 px，没从两块立石中间穿。整条连不起来：那两趟采集的轨迹在院门（x≈−49）本来就缺一段（`track_gate` 丢掉跨院门的段）
* **路线照老师的走法**：停靠点按录像时间顺序排：动作点（宝箱、毒花、精英怪），以及中间每次任务计数涨的时候人在哪（离上一个点 12 px 内的算同一处），点和点之间在走过的区域里规划。不要自己删点、改顺序、抄近路，老师怎么跑都是有考虑的；拿不准就问。「击败精英」这类任务把开打位置当 fight 点，普通敌人在途经点上碰到就打
* **简化的余量**：每段离边缘至少 1 px；录像里本来就窄的地方（规划的原路自己离边缘都不到 1 px），只要求不比原路更窄，不然会切成 0.5 px 一步

### 踩到的坑（2026-10-02，酒肉山林）

* **录像里的大地图要是最大缩放**：图标不随缩放变大，看起来像缩小的地图其实可能就是最大缩放。用刚关图后的小地图去配那张大地图，比例 2.28 正好对上，才确认
* **k 从录像里量**：配准和图标偏移都是小地图像素，单靠它们定不了比例（让 k 自由求解会塌成 0）；这一带大地图太空白也定不了（k 从 2.15 扫到 2.45 叠图分数都在 0.45–0.47）。院外 k 用小地图上「石碑 → 据点图标」对大地图上的同一段量。院内 k 这段录像量不出：两档的小地图纹理画法不一样，跨档直接配准只有 0.2–0.3 分；石碑在放大动画里就移出了小地图；所以取院外的一半
* **缩放切换是约 1 秒的动画**，不能按相邻帧找跳变；按两帧缩放比估计又会被移动和自相似纹理带偏（老是「2 倍」赢）。管用的是图标：沿同一方向 24 帧内远离 / 靠近 4 px 以上，走路做不到。图标超出范围时会钉在小地图边上（半径约 42–46），这种帧只给方向
* **跨档对齐用橙色区域的轮廓**：纹理对不上，但区域轮廓两档一样（相关 0.95），用来核对院内段的位置（剩 2 px 左右）。区域会在敌人死后变，只用切换前后、计数没变的那段
* **`map_locate.register` 有偏差**：同一张图配自己报 (−0.13, −0.20) px（模板按截到半径的掩码滤波；带掩码的相关峰不对称，抛物线细化偏一边），逐帧累加就漂。另外抛物线细化会「像素锁定」：30 帧里逐帧累加 1.30 px、直接配 2.06 px，短步长系统性偏短。工具里改成正反各配一次取平均、整数峰后用 ECC 细化，并且不用 1、3 帧这种短间隔（录像在画面不变时会补重复帧）
* **锚点不能被当成离群点剔除**：剔除门槛 2 px，有一轮锚点被丢了，整个解跟着拼图自我参照漂了 4–5 px
* **打架会打断帧间配准**：酒肉山林刚进院那 300 帧和后面之间隔着一场打，前段漂了 7 px，靠拼图定位那几轮拉回来
* **已攻占的据点**：灰色图标和石碑都要小地图模板（`templates/minimap_stronghold_done.png`、`minimap_stone.png`，各据点一样，从这段录像裁的）。活图标是 3×7 px 的暗红色块，用颜色找（H 165–10、S ≥ 85、V 40–150，敌人红点更亮更圆）
* **拼图覆盖多少事先算不准**：按拼图覆盖面积、每处用了多少帧算过「哪段没橙色的拼图够不够」，都和实际对不上（卡住那段算出来覆盖 0.8–0.96，比走通的院外段还高），所以靠 `dryrun` 实测、走不通就 `survey`
* **补采时开图短步走要加密路点**：它从当前位置直奔下一个点，29 px 的长段跑偏 4.5 px 撞上门洞的墙，原地开了 7 次图都没挪动；`survey` 每 4 px 插一个点，中途停了用 `--at x,y`（`where()` 读的）从最近的点接着走
* **箭头盖住据点图标**：30 px 内就可能盖住，`where()` 返回 null、补采停下；没有名字标签的据点靠石碑兜底（见上）
* **别用安卓返回键关大地图**：关掉以后再按一次就弹「确定退出当前账号?」；只点地图右上角的返回 (1025, 37)

## 给新据点（或新区域）做路线

用录像全自动做的流程见上一节；下面是老师边走边记点、开图采集的老流程

数据放在仓库根目录的 `data/wwm/`（不入库），命令都在仓库根目录跑，要先 `uv sync --extra cv`。

1. **传送节点**：照 `CixinTeleport` 做一个，裁这个据点卡片和石碑的模板
2. **录路点**：老师边走边说「记点」，用 `stronghold.js {where: true}` 读坐标；已有参考图的地方也可以用 `{locate: [...]}` 同时对比。**老师开走之前就开着抓帧**（下面第 3 步的 `grab_frames.py`），每次记点就是一个锚点（开图前最后一张大世界帧，位置是这次读的），老师这一趟就是第一趟采集；转弯、绕障碍的地方请老师多记几个点，路线按直线连点走，没记的弯会切角撞上（佛爷寨的草垛、立石）。新据点的名字标签也要裁一个（`where()` 的 `LABELS`）
3. **采集**：
   * 一边抓帧：`uv run python scripts/grab_frames.py data/wwm/survey<N> --seconds 1500`
   * 一边让路线用开地图的方式走一遍，每次开地图前停稳记锚点：`route {points, from, to, anchors: "teaching/survey/s<M>"}`
   * 锚点截图用 `maalow sync WhereWindsMeet --pull --screenshots` 拉回来；锚点列表（结果或日志里的 `anchor {...}`）存成 `data/wwm/survey<N>/anchors.json`，每条加上 `run`
   * 最好多走一趟，留作评测
   * 先量一下这个据点关掉大地图后小地图会不会先缩小（看据点图标在小地图上离箭头的距离，从关图后第一帧起是不是就和关图前一样）：不会就用 `track --gate X`（见佛爷寨）。开图走的路线没有参考图时很不稳，窄路差 1–2 px 就撞，**拼图做好之前别拿它给老师空跑**
4. **离线处理**（`uv run --extra cv python workspaces/WhereWindsMeet/tools/wwm_locate.py …`）：
   * `cache data/wwm --survey survey<N>`：截出每帧的小地图、判断是不是大世界画面、读镜头朝向
   * `track data/wwm --survey survey<N> --relocate mosaic_s1_s2_s3_s4`：用锚点加逐帧配准给每帧定位；链条漂移超过 4 px 的段改用已有参考图定位
   * `stitch data/wwm --runs s1,…`，再 `eval data/wwm --native data/build/locate.dll`：拼图，用没进拼图的那一趟评测。`mosaic*/overlay_*.png` 是把拼图叠到大地图上的检查图
   * `export data/wwm --runs s1,…`：写 `templates/locate/<name>_{mosaic,bigmap}.json` 和 PNG，然后 `maalow sync WhereWindsMeet --push`
5. **跑分**：`uv run python workspaces/WhereWindsMeet/tools/route_bench.py data/wwm/bench --refs locate/cixin_mosaic+locate/cixin_bigmap --rounds 3 --to 15`。每轮传送回石碑跑一遍、每点核对；失败重来，同一点连败 3 次就跳过
