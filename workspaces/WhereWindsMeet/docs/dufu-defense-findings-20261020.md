# 独夫防守：2026-10-20 调查结论

> 本文是这一轮从“离线攻击证据审计”到“实机诊断/A-B”的总收口。原始审计见 [attack-evidence-audit.md](attack-evidence-audit.md)；数据在 `data/attack_audit/20261020/` 与 `data/attack_triage/20261020/`。所有结论是代理证据，除 P0b 的确定性 bug 外，不是人工确认。

## 1. 一句话结论

**模型多数时候看得见，计划多数时候也在窗口内按了；真正卡住的是“按下去之后角色能不能动、有没有出架势”，而现有代码没有这个反馈。** 继续调 parry/dodge、阈值、固定 lead 不会提高通关率；先补执行/状态遥测，把每条 hit 分成“没执行 / 执行了但不可卸 / 执行了但时序错 / 根本没按”。

## 2. 证据链

### 2.1 离线审计（466 条候选接触）

- 466 = hit 134 + ok 332；90 样本中 hit 37 / ok 53。
- 精分后：接触估计早/晚 **39 条 / 2.344 maxHP**；固定 lead 早/晚 **9 条 / 0.495**；挨打后恢复按压 17 / 0.926；真正窗口内失败 **4 条 / 0.335**；被挡 21 / 1.079；忙碌 38 / 2.349；模型报了没动作 4 / 0.201；灰屏测量 2 / 0.500。
- 所以“按在最佳窗口还中”是小头；大头是状态/行动性、接触估计和资源。
- `ok` 不是干净的成功率：332 条里 193 条（58%）有玩家输出/蓄力混淆，OK_CLEAN 只有 139 条。不能用 `ok/min` 当防御率。
- 737 的 p90 29.53f 主要是 f5970–6051 的 7 次重复上报；去重后 p90 1.78f、max 9.37f，但不是全局时钟漂移。745 的 13.46f 是死亡末段灰屏单条。详见 `data/attack_audit/20261020/alignment_dedup.json`。

### 2.2 r748 实机诊断（`predMs=50`）

- 录像 `20261020-154901`，212s，dead，21 hit / 45 ok；dense `pred` 2408 条。
- 21 条 hit 里 19 条在命中前 10f 内有过 S1≥0.5 的预测；中位提前约 **15.9f**。模型不是“总是报晚”。
- 视频逐帧复核的关键案例：
  - **970 / 3947（各 11.4%）**：press lead 12–13f、计划误差 +1f，但玩家已经**俯卧/被按住**，卸势图标没亮。不是窗口内卸势失败，是长时间不可行动。
  - **2712（5.1%）**：玩家站立，Boss 横向长兵扫击；`def1` 连续 8f 说 `dodge`，计划却是 `parry`；按了仍中。防守类型/方向问题。
  - **2806（6.7%）**：S1 0.96、+12f，但当时在**幕布**里；`syncPlan` 因 `inCurtain` 跳过 `syncK`，根本没有 plan。不是 `off` 门控（此前误诊）。
  - **起幕布 5 条 / 约 34%**：首扫 dodge 在 dark sync +3f，hit 在 +4.4f；同步信号本身太晚。
- 倒地复核包 10 条：prone/held 6 / 0.684，knocked 3 / 0.291，standing 1 / 0.130。旧 4 条 normal（737/c020、745/c048、738/c018、733/c091）是同一“长柄横扫→俯卧”动作族；#6 是 `flare_grab` + dodge CD，#20 才是无金光近身击倒。

### 2.3 已否决的快速开关

| 开关 | A/B 结果 | 处理 |
|---|---|---|
| P0b 低血 `hpBase` + 红条优先 | 737 的 21/17 重复 hit 未复现，喝药正常 | **保留**（确定性 bug 修复，未证明提高通关率） |
| `curtainDodgeFirst` | 首扫 hit 4.3 vs 4.3，总 hits/oks 更差；按在 dark sync +3f 太晚 | 删除 |
| `dodgeMinP=0.35` | 1 次 cleared，但 dodge 次数没升、oks 更低 | 默认 0.5；cleared 当噪声记下 |
| `defDodgeReplan` | 触发正常，hit/min 6.93 vs 6.47，无下降；补的 dodge 距 hit 15.4f 偏早 | 删除 |
| `curtainParryPlan` | hit/min 5.55 vs 5.57，幕布少一点、normal 多一点，净零 | 默认 false |
| `offDefend` | 2806 根因是幕布，不是 off | 删除 |

可控 A/B 的 on/off 通关率都是 **1/12**；最近总共 2/25（8%）。3+3 样本对通关率没有分辨力，不能把单次 cleared 当归因。

### 2.4 为什么调参数没用

- 每个开关只改变“按多少次/按哪种”，不改变“按了有没有出架势”。
- 失败是异质的：幕布、倒地/被按住、出招后摇、硬直、CD、接触估计早/晚；一个开关只能动其中一小块。
- press 日志只证明触摸发出；游戏是否接受、角色是否在可行动状态、是否出了卸势架势，都没有逐事件记录。
- 没有视觉接触区间、没有逐推理 `def1` 概率、没有 press 后的架势/按钮光反馈，所以 A/B 只能看 hits/oks，无法归因。

## 3. 下一步：只加日志的遥测

不改变策略，默认关闭，跑 1–2 轮诊断：

1. **`pred` 记录 `def1` 各概率**（p0–p4）和 argmax；仍用 `predMs=50`。
2. **press 后 5–10f 记录执行反馈**：parry 按钮/卸势架势是否出现（模板或像素），dodge 按钮光/是否真的闪；日志写 `press result ...`。
3. **状态**：`inCurtain`、`staggerUntil`、`off` 当前动作、`hp`/`qi` 变化；倒地/被按住如果暂时没有可靠检测，先用视频+`stagger`/`hit` 时间近似，明确标 unknown。
4. 用 2712、970、3947、2806 四个已知案例验证：
   - press 发了但没架势 → **没执行**；
   - 有架势仍中 → **执行了但不可卸**；
   - 有架势但早/晚 → **时序错**；
   - 根本没有 press（幕布/倒地/硬直）→ **状态不可行动**。

拿到这些数据前，不再改默认参数、不再加防守开关。

## 5. 限制

- 没有视觉接触真值；`t = hp_drop − 5` 是检测器约定。
- `press` 是发送日志；`ok` 有 58% 输出混淆；`cleared` 是阶段一结束，不是完整胜率。
- 旧批 733/734 的 2/6 与当前 1/12 不可直接比较；参数/模型/批次不同。
- 所有 A/B 都是 3+3，轮间波动大于小效应；不能据此判断 10–20% 的通关率差异。
