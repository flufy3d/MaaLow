# 独夫：现状（2026-10-23）

试炼 → 开封皇宫 → 独夫 → 演练场（绝境·浴血·阶段一，不耗药、不降耐久），裂石钧（十方破阵 + 斩雪刀法）。`skills/dufu_enter.js` 进演练场，`skills/dufu.js` 打：

```
uv run maalow do skill dufu                                  # 默认 10 分钟、1 瓶药
uv run maalow do skill dufu --args '{"ms":300000,"potions":0}'
uv run maalow do skill dufu_enter --args '{"phase":2}'      # 阶段二：面板不是阶段二就用演练阶段下拉框切过去
uv run maalow do skill dufu --args '{"phase":2,"trace":true}'
```

结束原因：`cleared`（成功页模板连续两次命中，或任务栏出现「阶段二」，后者只在阶段一）、`dead`（再次训练按钮 / 长时间灰屏）、`time`。超过约 10 分钟的 `ms` 要同时给 `--timeout`（ms + 60000），否则 CLI 在 660 秒断开；脚本在超时前 15 秒自己收尾。

## 当前基线

dufu.js 现在只有一套行为：2026-10-20 第 737 轮的参数组合（当时叫 DPFCOMB）已经固化成代码常量，其余默认关的实验开关都删了（删除前做过对拍：新旧两版在 200 个随机场景里的触摸序列完全一致）。

| 指标 | 数值 |
|---|---|
| 通关率 | 约 8%（最近 25 轮 2 次；2026-10-21 复核 5 轮 1 次） |
| 主循环 | p50 31–35 ms，p95 102–107 ms |
| 模型 | `model/dufu/unified_back9.onnx`（MobileNetV3-Small，每帧 192 维）+ `unified_head9s.onnx`（两层因果 GRU，30 步 × [192 特征 + 15 aux]，无图像输入） |
| 推理 | App 侧特征环：backbone 每帧把特征和 aux 追加进环，head 直接读环（head p50 约 1 ms）；`ringBad` 是设备环和脚本自算的对账，应为 0 |

样本太少：5 轮或 3+3 轮的 A/B 对通关率没有分辨力，单次通关不能当成某个改动的功劳。

## 它在做什么

- **防守计划**：head 输出 fut1–3（下一次接触的帧距分布）、def1–3（卸势 / 闪避 / 幕布）、tell（金光三类 / 扫击 / 幕布 / 黑场）、combo（连段下一段的间隔）。每帧重建一份计划，按接触前 14 帧（亮 9 + 延迟 5）按下，临近 90 ms 冻结；按早了且接触后移会重新按（每项最多 2 次）。
- **金光**：tell 首报后按锚点帧闪避（grab 4、slam 10、other 14），左右交替；flare_other 首报后普通闪避先等锚点那一下（flareHold），3 帧后近处质量高的判为快招，提前到 6 帧（flareSplit）。
- **幕布**：tell、黑场或图像规则（暗面板 + 橙边）进入；进入后只撤计划里的闪避，卸势保留；按 65 帧周期定时后闪扫击，有缝就往缝里走。
- **挨打**：防守端不设受击硬直锁（血条掉血已滞后约 5 帧，实战一刀掉 ~30% 会按旧表误锁 500 ms），计划到点直接按；`onHit` 后 300 ms 内的卸势只走 220 ms 防连点 CD、不触发 330 ms 空按锁，300 ms 后同一接触 330 ms 内不重复卸势（游戏会锁）；受击后 250 ms 内若无防守按键且无挂起计划项，补一个兜底卸势。
- **喝药**：血 ≤35% 时等安静时机（离挨打、自己按键、计划项都够远，近处没有招），血涨 8% 才算喝到，没喝到 600 ms 后重按，最多 8 次。
- **进攻**：卸势成功 3 秒内或 boss 掉血后开「近门」：热血难凉时热蓄力，否则冷蓄力（近处 2 秒内来招概率 ≥0.7 不起手），新鲜成功时放唤千军，空档轻击；新鲜成功且爆发冷却好时整套横刀（切刀 → 突进 → 爆发 → 突进 → 伤害）；太久没打到就燃此魂 / 突进 / 前推近身。奇术只在开场或成功后放。横刀卸势成功后点蓝色爆发圆盘追击。
- **气竭**：真气读空且看到处决按钮后：轻击到 2.6 秒点处决，按钮消失就走近、再出现立刻点；窗口里不再防守（boss 不出手）。
- **其他**：成功页模板一出现就停止一切落指（演练下一阶段按钮压在锁定键上）；锁定图标灭了就补点锁定；开局短促前走直到 boss 条出现。

## 老师给的规则（一直有效）

- 输出全靠陌刀蓄力，蓄力一开始就要松手打出来；除了金光必须闪，什么都不能打断它。
- 金光闪避，红光卸势；金光不能卸。
- 低血时血条变红：灰条会把红条亮边读高（17% 读成 21%），所以低血优先读红条，受伤基线只跟随下降和确认的回血（737 曾把一次掉血算成 7 次挨打）。

## 试过、没用的（不要再从这些方向重来）

结论都来自实机 A/B 或逐帧复核，代码已删，细节在 git 历史里（`git log -- workspaces/WhereWindsMeet/docs/`）。

| 方向 | 结果 |
|---|---|
| 调参数 / 加开关（dodgeMinP、defDodgeReplan、curtainDodgeFirst、curtainParryPlan、offDefend 等） | hit/min 和通关率都看不出差别；每个开关只改「按什么、按几次」，不改「按了角色能不能动」 |
| grabParry（抓取标签改卸势） | 742–744：14 次接触只成功 1 次；抓取标签也会出现在普通挥砍上 |
| grabContactDodge / grabClass / 金色亮线 | 金色亮线、旧 flare3 分类器都分不开金光抓和普通金招；诊断配置本身还拖慢主循环 |
| 遥测（按键后 5–10 帧读按钮光） | 按钮光不能区分卸势成功与失败（亮和不亮之后出现 ok 的比例差不多），分类结论不成立 |
| curtainFlank（幕布起手绕后）、spinGuard（金光后旋转左右闪）、qiFront（气竭窗口里按老师顺序放技能）、offTang、offBuff、oldWindow、flareThreat | 都做成默认关试过，没有看出提升；offBuff 真正放出来的只有 22% |
| presched / closeIn / qiAttack（v5–v7） | combo 模板从来认不对（2.6%），被 v6 的间隔槽和 qiPlan 取代 |
| combat.js 的独夫模式（ttc / yolo / sweepNet / flareClass / defend 练习） | 统一模型出来之前的上一代做法，已整体换成 dufu.js |

2026-10-20 的结论仍然成立：模型多数时候看得见、计划多数时候在窗口内按了，挨打的大头是按下去时角色不可行动（俯卧、被按住、硬直、出招后摇）、幕布同步太晚和接触估计偏早偏晚；在没有可靠的「按下后是否出了架势」读数之前，继续调阈值和时机不会提高通关率。

## 阶段二（2026-10-23 起）

老师：红光多、卸势能接，金光照闪；阶段二没有幕布。2026-10-25 补充：远处打过来的一堆火球（火球雨）要先跑、再闪避，才躲得过；金光那招火球一个一个放、持续时间长的，只能闪避。跑法：

```
uv run python workspaces/WhereWindsMeet/tools/dufu_rounds.py data/p2 --n 10 --pull
uv run maalow do skill dufu --args '{"phase":2,"ms":900000}' --timeout 960000
```

`dufu_rounds.py` 每轮：进场 → 录像 → `dufu {"phase":2,"trace":"feat"}` → 停录 → 取 trace → `event_pad`（App 内存里只留最近 1000 条事件，trace 事件每条约 90 KB，堆积了 `GET /events` 会 OOM，`skills/event_pad.js` 用小事件把它们挤出去）。每轮存 `data/p2/rNNN/`（result、trace、args、录像 id），`--alt '[{...},{...}]'` 逐轮交替参数做 A/B。

`phase:2` 的行为：开局不上毒、不切道具格（老师：实战二阶段接着一阶段打，没有上毒的空窗期；道具格只放药，喝药前读到不是药才换回来）；任务栏的「阶段二」不算结束；fut/def 头的普通闪避改成卸势；不进幕布（tell 幕布类 / 暗场 / 图像规则都关）；气竭读空 300 ms 还没看到处决按钮就往前走（每段最多 4 秒，按钮一出现就停），走过的话最晚读空后 6 秒点处决。

**阶段二 head**（`unified_head_p2.onnx`，`phase:2` 时默认用它，`head` 参数可换；`tools/dufu_train/`）：back9 冻结，从 head9s 微调第二层 GRU 和输出头，trace 里存的就是设备上的 back9 特征；标签按旧文档（掉血帧 −5、卸势成功的真气台阶）。交叉验证覆盖率 61% → 92%，误触发持平；幕布误报清零。

**卸势时机分析**（89 轮，`data/tmp/p2timing/`）：大部分红色招没有各自的特殊时机，卸势在接触前 3–9 帧按下就接得住；挨打主要来自对接触时间的预测偏差（第一次按键的提前量四分位 11–35 帧）。有特定时机的只找到一类：红色水平亮线出现后 12–21 帧落地的招，在亮线后 +6 帧（+3..+15）按，成功率约 95%，估计每分钟少挨约 0.3 下（还没做：图像检测每次约 33 ms）。抓取过场（1/254）、重击后约 28 帧的火球齐射（4/102）怎么按都接不住，只能接住或闪开第一下；金光有一招能把满血直接打成重伤（r162）。

**红线卸势锚点**（`redLine`，阶段二，默认关，上机没有改善，见上表）：`--args '{"phase":2,"redLine":true}'`（数字 = 起点后几帧，默认 6）。每帧读红线（`lib/dufu-reads.js` `redLine`）：x=400 / 680 两条 4 px 竖条找细红块，候选行再用 120 px 短条、全宽 3 行带（≥220 px、跨度 ≥300）和上下 18–30 px 的 12 行侧带（平均行 < 0.25 倍）确认，行范围 y 152–470；平时 2 次 color()，有候选 3–6 次（估计约 2–3 ms/帧，按 hp/qi/lit 约 0.8 ms/次推算；均值超过 5 ms 自动隔帧）。离线回放 29 轮 7.6k 帧（`data/tmp/p2timing/rl/`）：真红线起点 +2 帧内检出 62%，比离线规则多报的帧 0.7%。时间：分析里是按键时刻（Date.now()）减视频起点帧，视频帧对应抓帧时刻，所以锚点 = 红线帧的抓帧时刻（img.time − img.age_ms）+ 6 帧，LATENCY_F 已含在统计里；实际按下约在起点 +6..+8 帧。规则：一段红线（帧间隔 ≤3.5 帧）只算一次；ok / 挨打读数落在起点前 2 帧到后 6 帧（即接触后 8 帧内的冲击闪光）就忽略，已排的卸势撤掉；窗口 [+3, +15] 帧：之前要按的 fut 卸势推到锚点，窗口里已有 fut 卸势就不另加，否则加一个 red 卸势（等 CD / 锁定，过了窗口就放弃）；窗口里按过一次后其余的撤掉。结果里 `redLine`：onsets / ignored / moved / covered / presses / pressF（实际按下在起点后几帧）/ after（按后第一个 ok / 挨打）/ readMs / calls。

**节拍卸势**（`cadence`，阶段二，默认关，上机没有改善，见上表；依据和规格见 `tools/dufu_train/README.md` 的离线回放和「dufu.js 集成规格」）：`--args '{"phase":2,"head":"dufu/unified_head_p2e.onnx","cadence":0.1}'`（数字 = 门限 G，回放 0.05 ≈ 115 按键/分，0.1 ≈ 100，0.15 ≈ 88）。G = head 输出 lead1f（out[133..178]，softmax）第 2–16 帧档之和；head 没有这 46 列（输出不足 179）时节拍不开，结果 `cadence.off` 写原因。脚本记「游戏最后一次执行的卸势」exeAt（任何来源的卸势落指：距 exeAt ≥ 330 ms 或其后有 ok 才算执行，否则记为被锁吞掉），锁到 exeAt + 330（有 ok 解锁）；每帧 G ≥ 门限、锁结束 +15 ms、距上次卸势 ≥ 220 ms、不在硬直 / 喝药保持 / 闪避 / 气竭窗口、100 ms 内没有要按的闪避、没有待按的药，就按一下卸势（标记 `press parry cadence G0.xx`）。紧急喝药（hp ≤ 15% 或已等 2.5 s）时节拍最多让 600 ms。开着时不跑 syncK（fut 卸势、分支、重按、relock 等待）、expire 的重按、挨打逃脱和保险卸势；金光 / tell 闪避、处决照旧；喝药的安静条件改成 G < 门限（不看 fut1 质量）；进攻（近身门的各动作、横刀整套起手、远距贴近、奇术 / 追击）要求 G < 门限；红线锚点的卸势也要等节拍的锁，两者不会在一次锁里各按一下。结果里 `cadence`：presses、touches（全部卸势落指）、swallowed（估计被锁吞掉的）、openShare（门限开着的帧比例）、gapHist / gapMs（相邻卸势落指间隔，应集中在 345–380 ms）、yields、wait（门限开着但没按的原因计数）。

**挨打归因**（4 轮 p2 头，`data/tmp/p2hits/`）：模型每次都有计划和按键。掉血大头是金光开场的一串（43%，抓取一次 5 下约 24% 血）、按了卸势仍挨打的单发（35%，按键时机分布和成功的一样，像是招本身接不住：血龙横扫、台阶上的远程齐射 / 喷火、火焰鬼面、地面爆裂）、红色连段后续（18%）。boss 掉血一半来自处决（每次约 16%），陌刀蓄力在阶段二几乎不放（冷蓄力被禁、热蓄力很少满足）。
