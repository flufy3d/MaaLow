## 核心思路

- 以 boss 为中心裁剪着看，不再整屏压成 96×96。
- 认出是哪一招，照这一招的时间表落指。
- 颜色定动作（红光卸势、金光闪避，老师定的），招式定时间（第几帧按）。
- 兜底都在新模型里：认不出招时用同一模型的通用头（光的颜色 + 接触时间）；颜色也拿不准就闪。不依赖旧的 `dufu.js`。

## 运行时（Pad，每帧约 10 ms 内）

```
抓屏 → ① 全局流（整屏低分辨率：大范围光效、距离）
     → ② 裁剪流（boss 区域：起手动作细节）
     → ③ 时序模型
          · 招式头：哪一招、起手后第几帧、置信度
          · 通用头：光的颜色、接触时间
     → ④ 决策层（招式表 + 动作原语：卸 / 闪 / 处决 / 喝药）
```

- 裁剪先用固定的中心双框（锁定后 boss 基本在画面中间：大框 530 → 192 管贴脸和大招，小框 260 → 192 管中远距离的起手）；录像统计证明有必要再加学出来的定位。
- 招式表每局之后自动修正：每招的提前量、能不能卸。

## 模型

- 每个 boss、每个阶段单独一个模型，不共享骨干网络；新模型从上一个训好的权重起步，全部重训，不冻结。
- 实战开局两个阶段的模型都加载，看到阶段信号就切换，阶段一快结束时阶段二的模型先在后台热起来。

## 招式分类：全自动

- 自动切片：接触、挨打、卸势成功事件加运动量，找起手帧。
- 自动聚类：类别数自动定，招式只有编号，不起名字。很多招起手一样、后面才分叉，所以招式按「到当前这一下为止」认（前缀）：分不开的类在分叉前合成一组，每一下重新认一次。
- 自动检查：同类里接触节奏分两拨就拆；两类节奏和应对一样就并；同类里金红混在一起，按颜色拆。
- 新招先归「未知」，由通用头处理，攒够了自动成新类。
- 好不好看实战结果（这一类卸 / 闪的成功率），不看人工标签。
- 网页上可以随时看各类样例和成功率，拆、并、改颜色，下次重训生效；没人看，流程照跑。

## 训练（PC，5080）

自动切片 → 自动聚类 → 大模型（老师）→ 蒸馏成小模型（学生）→ 量化 → PC 和 Pad 逐帧对拍。全程无人值守。

## 自动闭环

```
无人跑局（演练场）→ 入库 → 自动切片和聚类 → 重训 → 离线关卡
→ 影子模式上机 → 擂台（新旧模型 8 对 8 交替）→ 更好就升级，否则丢弃 → 回到跑局
```

- 人工纠错只是输入，不是一步。
- 每天自动出报告：各类成功率、升级 / 丢弃记录、异常。
- 无人值守要处理：游戏闪退 / 卡加载重进，Shizuku 掉了重启，过热暂停，存储低暂停，连续失败熔断后通知。录像拉到 PC 后从 Pad 删掉。

## NPU：MaaLow 的可选插件

- QNN 运行时和高通的库单独打包、单独发版，不进主 App，不碰 MaaFramework 自带的 onnxruntime。
- 没装：`infer()` 走 CPU。装了：多一个 `qnn` 选项，skill 写法不变。
- 训练流水线同时出 CPU 版和 QNN 版模型，用哪份看设备上有没有插件。
- 接通顺序：先试现有的 `nnapi` → Qualcomm AI Hub 云端真机测耗时（已同意上传模型权重）→ 做插件。走不通就用 CPU，模型小一号。

## 分层（以后接别的 boss）

- 引擎（共用）：裁剪、决策引擎、训练流水线、闭环、纠错网页。
- NPU 插件（可选）。
- boss 包（每个 boss / 阶段一份）：进场方式、HUD 位置、规则（光怎么应对、特殊机制）、招式表、模型。
- 配招包（按武器）：输出、喝药。
